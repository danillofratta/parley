# Domain model standard (all services, all stacks)

Every service uses the same domain building blocks. The concepts, names and
rules are identical in Go, .NET and Python; only the language mechanism changes.
The reference implementations live in `.claude/skills/new-service/seedwork/`
and are copied into each service as `domain/seedwork` (`Domain/SeedWork` in .NET).

## Domain folder layout

The domain is organized by building block, so a large domain stays navigable.
Same folders in every stack:

| Folder | Go package | .NET folder / namespace | Python package | Content |
| --- | --- | --- | --- | --- |
| seedwork | `seedwork` | `SeedWork` | `seedwork` | Base building blocks (copied from the standard) |
| enums | `enums` | `Enums` | `enums` | Enums |
| rules | `rules` | `Rules` | `rules` | Business rules |
| value objects | `valueobjects` | `ValueObjects` | `value_objects` | Value objects |
| events | `events` | `Events` | `events` | Domain events |
| entities | `entities` | `Entities` | `entities` | Aggregate roots and entities |
| repositories | `repositories` | `Repositories` | `repositories` | Repository ports |
| services | `services` | `Services` | `services` | Domain services (only for logic that spans aggregates) |

```
domain/
  seedwork/
  enums/
  rules/
  valueobjects/        (ValueObjects in .NET, value_objects in Python)
  events/
  entities/
  repositories/
  services/            (only when needed)
```

### Dependency order inside the domain

Folders may only import folders to their left. This prevents import cycles
(mandatory in Go, good hygiene in .NET and Python):

```
seedwork <- enums <- rules <- valueobjects <- events <- entities <- repositories <- services
```

- Rules receive primitives, enums or small interfaces (e.g. `IsZero()`), never
  entities, so value objects and entities can both use them.
- Events carry ids and value objects, never entities.

### Growing domains

- .NET and Python: when a folder holds more than one aggregate, add one
  subfolder per aggregate (`Entities/Conversations/Conversation.cs`,
  `Rules/Conversations/ConversationMustBeOpen.cs`).
- Go: subpackages per aggregate would create cycles; keep the folder flat and
  prefix file names with the aggregate (`conversation.go`,
  `conversation_rules.go`, `conversation_message.go`).
- One type per file in .NET; one concept per file in Go and Python (a rules
  file may group the rules of one aggregate).

## Building blocks

| Block | Purpose | Go | .NET | Python |
| --- | --- | --- | --- | --- |
| Entity | Identity + audit trail + version; equality by `Id` | embedded `seedwork.Entity` | `abstract class Entity` | `class Entity` |
| Aggregate root | Entity + `TenantId` + domain events; consistency boundary | embedded `seedwork.AggregateRoot` | `abstract class AggregateRoot : Entity` | `class AggregateRoot(Entity)` |
| Value object | Immutable, validated on creation, equality by value | comparable struct, unexported fields | `record` | `@dataclass(frozen=True)` |
| Enum | Closed set of values | named `int` type + `iota`, `String()`, `Parse<Enum>()` | `enum` | `enum.StrEnum` |
| Domain event | Business fact in past tense | struct embedding `seedwork.EventBase` | `record : DomainEvent` | `@dataclass(frozen=True) (DomainEvent)` |
| Business rule | Invariant named in the ubiquitous language | type implementing `seedwork.BusinessRule` | class implementing `IBusinessRule` | class implementing `BusinessRule` |
| Repository | Persistence port, one per aggregate root | interface in `domain` | `interface : IRepository<T>` | `Protocol` |

## Entity

Every entity has, at minimum:

| Field | Type | Rule |
| --- | --- | --- |
| `Id` | UUID v7 | Generated by the domain at creation, never by the database |
| `CreatedAt` | timestamp (UTC) | Stamped by persistence on first save |
| `CreatedBy` | actor | `user:<id>` or `system:<service>`, stamped by persistence |
| `UpdatedAt` | timestamp (UTC), nullable | Stamped by persistence on every update |
| `UpdatedBy` | actor, nullable | Stamped by persistence on every update |
| `Version` | integer | Optimistic concurrency; 1 on insert, +1 on every update |

- Entities are compared by `Id` only.
- Audit fields are read-only for the domain. Persistence stamps them from the
  clock and the current actor (EF Core interceptor in .NET; an `Auditor` used by
  repositories in Go and Python).
- Business attributes (name, status, dates of business meaning such as
  `ReceivedAt`) are added per entity as the domain requires.
- Soft delete only when the business requires it: `DeletedAt`, `DeletedBy` and
  a `Delete(...)` behaviour; repositories filter deleted rows.

## Aggregate root

- Adds `TenantId` (every aggregate belongs to exactly one tenant) and the list
  of domain events raised since it was loaded.
- Created through a factory method named after the business action
  (`ReceiveMessage`, `OpenConversation`), never through a public constructor
  with loose fields.
- State changes only through behaviour methods; no public setters.
- Raises domain events inside its behaviour; the repository writes them to the
  outbox in the same transaction and then clears them.
- References other aggregates by `Id`.

## Business rules

- Each invariant is a small type named in the ubiquitous language
  (`MessageMustHaveText`), with `IsBroken()`, a stable `Code`
  (`inbound_message.text_required`) and a human `Message`.
- Entities and value objects call `CheckRule(rule)`. A broken rule produces the
  single standard violation type (`BusinessRuleViolation` error in Go,
  `BusinessRuleViolationException` in .NET and Python's `BusinessRuleViolation`).
- There are no ad-hoc error types or catch-all error files in the domain.
- Entry points map a violation to the protocol: HTTP 422 with the rule `Code`,
  or "acknowledge without retry" for webhooks and consumers.

## Domain events

Every event carries `EventId` (UUID v7), `OccurredAt`, `AggregateId` and
`TenantId`, plus its business fields. `EventId` becomes the integration event's
`messageId`, so Inbox deduplication works end to end.

## Repositories

- `GetById(tenantId, id)`, `Add(aggregate)`, `Update(aggregate)`; nothing
  query-like (queries belong to query slices).
- Standard outcomes, same meaning in every stack: not found (`ErrNotFound` /
  `null` / `None`), already exists (`ErrAlreadyExists` /
  `AggregateAlreadyExistsException` / `AggregateAlreadyExists`) and concurrency
  conflict (`ErrConcurrencyConflict` / `ConcurrencyConflictException` /
  `ConcurrencyConflict`).
- `Update` checks `Version`: `UPDATE ... WHERE id = $1 AND version = $2`.

## Database columns (every aggregate table)

```sql
id          UUID        PRIMARY KEY,
tenant_id   UUID        NOT NULL,
-- business columns
created_at  TIMESTAMPTZ NOT NULL,
created_by  TEXT        NOT NULL,
updated_at  TIMESTAMPTZ,
updated_by  TEXT,
version     INT         NOT NULL
```

Natural business keys (e.g. a provider's message id) get a `UNIQUE` constraint
that includes `tenant_id`.

## Dependencies allowed in the domain

Standard library plus a UUID v7 generator: `github.com/google/uuid` (Go),
`Guid.CreateVersion7()` (.NET), `uuid.uuid7()` (Python 3.14+, or the `uuid6`
package on older versions). Nothing else.
