# ADR-0014: Domain building blocks standard

- Status: Accepted
- Date: 2026-10-01

## Context

Parley is a corporate, multi-tenant system built in three stacks. Without a
shared standard, each service models identity, auditing, concurrency and
business-rule violations differently, which makes the code harder to review,
operate and audit.

## Options

### Model case by case
Fewer files for small services; inconsistent identity, auditing and error
handling across services.

### One shared library for all services
Impossible across three languages, and a shared runtime library couples
deployments.

### One standard, one reference implementation per stack (chosen)
The same concepts and rules everywhere (`Entity`, `AggregateRoot`, value
objects, enums, domain events, business rules, repositories), implemented
idiomatically and copied into each service's `seedwork`.

## Decision

Adopt `.claude/rules/domain-model.md`. Every entity has `Id` (UUID v7
generated by the domain), `CreatedAt`, `CreatedBy`, `UpdatedAt`, `UpdatedBy`
and `Version`; every aggregate root has `TenantId` and domain events;
invariants are business-rule types checked with `CheckRule`, producing one
standard violation type.

## Consequences

- Positive: uniform auditing and optimistic concurrency; the same review
  checklist for every service; rule codes give clients stable error contracts.
- Negative: more structure for thin supporting domains (Channel Gateway); the
  seedwork is duplicated per service by design.
- Simplifications compared with production: `CreatedBy` is a plain actor string
  (no user directory yet); no field-level audit history.
